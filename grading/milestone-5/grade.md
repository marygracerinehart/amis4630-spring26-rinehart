## 5. Code Quality Coaching (Non-Scoring)

- **Admin password strength**: [DbSeeder.cs](BuckeyeMarketplace/backend/BuckeyeMarketplaceAPI/Data/DbSeeder.cs#L247) seeds the admin user with password `Admin123` which is weak and doesn't require a special character. Consider using a stronger default and/or requiring password change on first login.

- **CORS configuration**: [Program.cs](BuckeyeMarketplace/backend/BuckeyeMarketplaceAPI/Program.cs#L19-L22) falls back to `SetIsOriginAllowed(_ => true)` when `FrontendUrl` is not set. In production, this effectively allows any origin. Ensure `FrontendUrl` is always set in non-development environments.

- **Token refresh race condition**: [apiClient.js](BuckeyeMarketplace/frontend/src/services/apiClient.js) handles concurrent refresh deduplication well with the `isRefreshing` flag — good pattern. However, the `clearAuthData()` call on refresh failure doesn't trigger a React state update, so the UI may remain in a stale "logged in" state until the next render cycle.

- **App.test.js**: [App.test.js](BuckeyeMarketplace/frontend/src/App.test.js) still contains the default CRA test (`renders learn react link`) which fails because the app no longer renders that text. This dead test should be updated or removed.
